## TotalRepeats в двух словах

TotalRepeats — это *самокалибрующийся поиск семейств повторов без выравнивания и их пангеномное сравнение* в одной программе. Одна команда проводит FASTA-файл или папку с геномами через весь анализ повторов, не оставляя ничего второму инструменту:

- **Один инструмент для всей задачи.** Поиск коротких тандемных повторов, обнаружение повторов *de novo*, мягкое маскирование, кластеризация копий в семейства, определение цепи, необязательное именование по библиотеке, готовые к публикации рисунки и — для нескольких геномов — полный пангеномный анализ, всё за один запуск. Нет конвейера сторонних программ, которые нужно устанавливать, настраивать и поддерживать совместимыми.
- **Устанавливать нужно только Java.** Один JAR без внешних зависимостей, без базы данных и без этапа сборки. Один и тот же файл работает на Windows, Linux и macOS, на ноутбуке и на узле HPC-кластера.
- **Библиотека повторов не требуется.** Повторы обнаруживаются в самой последовательности по частоте k-меров, поэтому TotalRepeats находит повторы, которые действительно присутствуют в геноме, — включая отсутствующие во всех курируемых базах данных — и работает для любого организма. Библиотека (Repbase, Dfam/FamDB или собственный FASTA) необязательна и используется только для именования найденных семейств.
- **Без выравнивания — и потому быстро.** Выравнивание «все против всех» никогда не выполняется: детекция подсчитывает k-меры за один потоковый проход по обеим цепям, а семейства строятся сравнением компактных профилей состава. На 4-ядерном настольном компьютере бактериальный геном обрабатывается за секунды, а эукариотическая хромосома длиной 15 Mb — примерно за минуту от начала до конца (см. [Измеренное время работы](#измеренное-время-работы)).
- **Самокалибрующиеся пороги.** Копия присоединяется к семейству, когда её сходство с затравкой (seed) семейства превышает порог случайного сходства, *измеренный по данным самого запуска*, отдельно для каждого класса длин блоков, а не фиксированный порог идентичности последовательностей. Уровень принятия решения, таким образом, подстраивается под распределение длин и нуклеотидный состав анализируемого генома. При проверке выравниванием Смита–Ватермана на реальных геномах 98–100 % пар «затравка–член семейства», объединяемых мерой по умолчанию, подтверждаются как гомологичные (см. [Меры кластеризации](#меры-кластеризации)).
- **Детерминированный и воспроизводимый.** Кластеризация по умолчанию выполняется на всех ядрах процессора, и её результат побайтово идентичен при любом числе потоков. Кривые разрежения (rarefaction) пангенома вычисляются точно, а не случайными перестановками. Каждый выходной файл несёт идентификатор выпуска, которым он создан.
- **Масштаб пангенома.** Сравнительные режимы адресуют все входные файлы 64-битными координатами поверх виртуальной конкатенации, поэтому суммарный объём входных данных ограничен оперативной памятью, а не пределом Java в 2.1 Gb на одну последовательность. Пангеномный отчёт даёт семейства core / soft-core / shell / cloud, разрежение с оценкой открытости по закону Хипса, расстояния Жаккара и Брея–Кёртиса между геномами с деревом UPGMA, паттерны присутствия и вариацию числа копий.
- **И обратный вопрос тоже.** `-homology` маскирует всё гомологичное внутри геномов и между ними и оставляет последовательность, *уникальную* для каждого, а `-extunique` записывает эти области в файл — один и тот же движок отвечает на вопросы «что повторяется?» и «что представлено в единственной копии?».

## Обзор

TotalRepeats — инструмент *de novo* для полногеномной идентификации, классификации, аннотации, визуализации и пангеномного сравнения повторяющихся элементов ДНК. Он обнаруживает широкий спектр типов повторов, включая:

- **Мобильные генетические элементы** — ретротранспозоны (LINE, SINE, LTR-элементы) и ДНК-транспозоны
- **Тандемные массивы** — микросателлиты (SSR), минисателлиты, теломерные повторы, центромерная сателлитная ДНК
- **Дупликации генов** — дуплицированные гены и варианты числа копий
- **Крупномасштабные структурные вариации** — сегментные дупликации, перестройки

Инструмент предназначен для сравнительной геномики, эволюционной биологии, исследований структурных вариаций и общего биоинформатического анализа. Он масштабируется от одного локуса до пангенома: одна и та же команда анализирует одну последовательность, каждую запись FASTA-файла с несколькими записями, каждый файл в папке или папку сборок, сравниваемых совместно. Детекция повторов — один потоковый проход по k-мерам обеих цепей; кластеризация семейств и аннотация по библиотеке **многопоточны** и выполняются на всех доступных ядрах процессора как на рабочей станции, так и на HPC-оборудовании. Измеренное время работы приведено в разделах [Бенчмарк](#бенчмарк-чувствительность-и-скорость-на-смоделированных-геномах) и [Измеренное время работы](#измеренное-время-работы).

Кроме того, режим `-homology` обращает поиск и сообщает **уникальную (однокопийную) последовательность** — области, встречающиеся лишь один раз во всём геноме или в пределах отдельной хромосомы (см. [`-homology`](#-homology--маскирование-гомологии)).

## Ключевые возможности

| Возможность | Описание |
|---|---|
| 🔍 **Детекция *de novo*** | Идентификация на основе k-меров всех классов повторов, перечисленных в [Обзоре](#обзор), — без предварительной библиотеки повторов и без таксон-специфичных допущений |
| 🧪 **Самокалибрующаяся кластеризация** | Копии группируются в семейства относительно порога случайного сходства, измеренного по данным самого запуска для каждого класса длин, а не фиксированного порога идентичности; 98–100 % сгруппированных пар подтверждены выравниванием на реальных геномах |
| 🧬 **Сравнительный анализ** | Анализ нескольких геномов или сборок одновременно с синхронизированной кластеризацией повторов: одно и то же семейство сохраняет тот же `ClusterID`, цвет и метку в каждом пофайловом и в объединённом отчёте |
| 🔀 **Детекция полиморфизмов** | Выявление полиморфизмов присутствия/отсутствия повторов между геномами (внутри- или межвидовых) без полногеномного выравнивания |
| 🧩 **Пангеномный анализ** | Классификация семейств core / soft-core / shell / cloud, точные кривые разрежения с оценкой открытости по закону Хипса, расстояния Жаккара и Брея–Кёртиса между геномами с деревом UPGMA, паттерны присутствия, вариация числа копий, матрицы числа копий и bp и сводный рисунок — в каждом сравнительном режиме (`-collate`, `-joint`, `-combinemask`) |
| 🗄️ **Входные данные масштаба пангенома** | Сравнительный анализ не ограничен пределом ~2.1 GB на одну последовательность — входные данные конкатенируются виртуально и адресуются 64-битными координатами |
| 📚 **Внешняя аннотация** | Именование семейств повторов по Repbase, Dfam/FamDB или собственной видоспецифичной библиотеке (необязательно) |
| 🔎 **Уникальная последовательность** | `-homology` маскирует всю гомологичную последовательность внутри геномов и между ними и оставляет однокопийную; `-extunique` извлекает эти области |
| 📊 **Векторная и растровая визуализация** | Ландшафты повторов в PNG и SVG, аннотированные карты и сравнительные представления с настраиваемыми размерами (`image=`, `imgx=`) |
| ⚡ **Детерминированная многопоточность** | Кластеризация и аннотация по умолчанию выполняются на всех ядрах (`-normal` принудительно задаёт один поток) и дают **идентичный, воспроизводимый** результат при каждом запуске, каким бы ни было число потоков |
| 📦 **Нулевые зависимости** | Один JAR, Java 25+ и ничего больше; набору тестов (297 проверок) нужен только JDK |
| 🏷️ **Происхождение результатов** | Идентификатор выпуска печатается командой `-version`, в начале каждого запуска и в заголовке каждой таблицы аннотации |

## Как это работает

```
┌──────────────────────────────────────────────────────────────────────────┐
│                       Конвейер TotalRepeats                              │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  1. ВХОД                     2. МАСКИРОВАНИЕ                             │
│  ┌────────────────┐          ┌─────────────────────────────┐             │
│  │ Файлы FASTA    │────────▶ │ Поиск STR/низкой сложности  │             │
│  │ (файл/папка)   │          │ Подсчёт k-меров, обе цепи   │             │
│  └────────────────┘          │ Покрытие → блоки повторов   │             │
│                              └─────────────┬───────────────┘             │
│                                            │                             │
│  3. КЛАСТЕРИЗАЦИЯ                          ▼                             │
│  ┌──────────────────────────────────────────────────────────┐            │
│  │ • Группировка копий повторов в семейства по сходству     │            │
│  │ • Классы: тандемные (STR), некластеризованные (UCRP),    │            │
│  │   кластеризованное семейство (CRP), с указанием цепи     │            │
│  │ • Параллельное сравнение: состав 4-меров (по умолчанию), │            │
│  │   или вложенность k-меров с -contain                     │            │
│  └─────────────────────────┬────────────────────────────────┘            │
│                            │                                             │
│  4. АННОТАЦИЯ              ▼               5. РЕЗУЛЬТАТЫ                 │
│  ┌──────────────────────────┐    ┌──────────────────────────┐            │
│  │ Именование семейств по   │───▶│ Таблицы аннотации        │            │
│  │ Repbase / Dfam / своей   │    │ Маскированный FASTA      │            │
│  │ библиотеке (опционально) │    │ Изображения PNG / SVG    │            │
│  └──────────────────────────┘    │ Сводная статистика       │            │
│                                  │ Пангеномный отчёт        │            │
│                                  └──────────────────────────┘            │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

1. **Ввод** — читает один или несколько FASTA-файлов (или целую папку геномов). Каждая запись файла с несколькими записями анализируется отдельно.
2. **Маскирование** — находит короткие тандемные повторы и участки низкой сложности по скользящей оценке разнообразия, затем подсчитывает все k-меры на обеих цепях, отмечает покрытие каждого основания k-мерами, встречающимися не менее двух раз, и объединяет покрытые участки в блоки повторов. Результат — мягко маскированная последовательность и координаты блоков.
3. **Кластеризация** — группирует блоки повторов в семейства по сходству последовательностей в обеих ориентациях и записывает цепь каждой копии; каждый блок в итоге оказывается тандемным повтором (`STR`), некластеризованным диспергированным повтором (`UCRP`) или членом кластеризованного семейства (`CRP`).
4. **Аннотация** *(необязательно)* — сопоставляет каждое семейство с Repbase, Dfam/FamDB или собственной библиотекой и помечает его совпавшей записью.
5. **Результаты** — создаёт таблицы аннотации повторов, мягко маскированный FASTA, изображения PNG и SVG, сводную статистику и, для сравнительного запуска, пангеномный отчёт.

## Установка

### Вариант 1: прямая загрузка

```bash
# 1. Клонируйте репозиторий (или скачайте JAR напрямую)
git clone https://github.com/rkalendar/TotalRepeats.git
cd TotalRepeats

# 2. Убедитесь, что доступна Java 25+
java -version

# 3. Запустите — сборка не требуется
java -jar dist/TotalRepeats.jar genome.fasta -out=/path/to/results/
```

### Вариант 2: через Conda

Если Java 25 не установлена в системе:

```bash
# Создайте отдельное окружение
conda config --add channels conda-forge
conda config --set channel_priority strict
conda create -n java25 openjdk=25
conda activate java25

# Проверьте
java -version
```

### Запуск набора тестов

Репозиторий содержит самодостаточный набор тестов, покрывающий чтение последовательностей,
k-мерные таблицы, арифметику координат виртуальной конкатенации, извлечение блоков маски,
пангеномную статистику и обработку командной строки. Ему не нужно ничего, кроме JDK, —
не требуется устанавливать ни JUnit, ни другие внешние зависимости:

```bash
./run-tests.sh          # Linux/macOS
run-tests.bat           # Windows
```

Скрипт компилирует `src/` вместе с `tests/` и запускает `TestRunner`, который печатает каждую
проверку и завершается с ненулевым кодом, если какая-либо из них не прошла, так что им можно обусловить сборку или задание CI:

```
PASSED  297 checks in 3.6 s
```

| Набор | Проверок | Покрывает |
|---|---|---|
| `DnaTest` | 27 | комплемент / обратный комплемент, коды IUPAC, нормализация, стабильность общей таблицы |
| `FastaReaderTest` | 28 | разбор записей, нормализация IUPAC, «сырой» режим с сохранением мягкой маски, текст перед первым заголовком, последовательности без заголовка (и текст, который ею не является), немодифицируемые аксессоры |
| `SeqStoreTest` | 28 | границы сегментов, перевод глобальных координат в локальные, подстроки, пересекающие сегменты |

## Использование

### Базовый синтаксис

```bash
java [JVM flags] -jar TotalRepeats.jar <input_file_or_directory> [options]
```

- **Входные данные** могут быть одним FASTA-файлом или папкой с несколькими геномами. Они должны быть **первым** аргументом. Сравнительные режимы (`-collate`, `-joint`, `-combinemask`, `-homology`) действуют только на **папку**; при одиночном файле они молча игнорируются и выполняется обычный анализ одного файла. Если входные данные — папка, файлы, созданные самим TotalRepeats, пропускаются, а не анализируются заново, так что папку можно безопасно обработать повторно после того, как предыдущий запуск записал туда свои результаты. Проверка учитывает режим: файлы `.msk` по-прежнему читаются режимами `-readmask`, `-extunique` и `-combinemask`, а файлы `.gff` — режимом `-readgff`; изображения и пангеномные отчёты никогда не считаются входными данными. Число пропущенных файлов сообщается в начале запуска.
- **Опции** следуют за входным путём и могут указываться в любом порядке. Каждый аргумент разбирается как один токен и сопоставляется точно: имена нечувствительны к регистру, а ведущий дефис необязателен (`joint`, `-joint` и `--joint` эквивалентны). Нераспознанная опция сообщается в stderr и пропускается. Путь, в котором случайно встречается имя опции (скажем, папка с именем `joint_genomes`), никогда не принимается за опцию.
- **Папка результатов** задаётся опцией `-out=<path>` (по умолчанию — папка входного файла). Позиционного аргумента для вывода нет.
- Дополнительные зависимости не требуются.
- **Нужна справка?** Запустите с `-help`, `--help`, `-h`, `--h`, `-?`, `--?`, `/?`, `/h`, `/help`, `help`, `?`, `-usage`, `--usage` или `/usage` (без учёта регистра) либо вовсе без аргументов, чтобы напечатать полную справку и выйти. Справка также показывается, если указанный входной файл или папка не существует.

### Настройка памяти

При работе с большими геномами выделите дополнительную память кучи (heap) флагами JVM:

| Наибольшая одиночная последовательность (оснований) | Рекомендуемая ОЗУ | Флаги JVM |
|---|---|---|
| < 100 Mb | Куча JVM по умолчанию | Нет |
| 100–500 Mb | 16 GB | `-Xms8g -Xmx16g` |
| 500 Mb – 2 Gb | 32 GB | `-Xms16g -Xmx32g` |
| > 2 Gb | 80 GB или больше (куча плюс накладные расходы ОС и JVM) | `-Xms32g -Xmx64g` |

**Что означают флаги:**

- **`-Xms`** (начальная куча) — память, выделяемая заранее при запуске. Позволяет избежать дорогостоящего изменения размера во время выполнения.
- **`-Xmx`** (максимальная куча) — верхний предел памяти. Предотвращает `OutOfMemoryError` на больших геномах.

> **Совет:** задайте `-Xms` примерно вдвое меньше `-Xmx`, как в таблице выше, чтобы куча была заранее подобрана близко к рабочему набору и дорогостоящее изменение её размера во время запуска не требовалось.

> **Сравнительные запуски (`-collate`, `-joint`, `-combinemask`):** подбирайте размер кучи по *суммарной* длине всех входных файлов, а не по наибольшему файлу. На суммарную длину не распространяется предел ~2.1 GB на одну последовательность, поскольку входные данные конкатенируются виртуально и адресуются 64-битными координатами; главным ограничением становится доступная куча, тогда как каждая отдельная последовательность по-прежнему ограничена.

## Подробное описание опций

### `kmer=` — Размер k-мера

Задаёт длину k-мера для маскирования повторов (диапазон: 9–21). Более короткие k-меры обнаруживают более короткие повторы, но увеличивают время работы и шум; более длинные k-меры специфичнее, но пропускают короткие элементы.

| Диапазон k-мера | Лучше всего для | Примеры |
|---|---|---|
| 9–12 | Очень короткие повторы | Спейсеры CRISPR |
| 13–17 | Малые хромосомы, геномы органелл | Митохондрии, пластиды, бактерии |
| 18–21 | Эукариотические хромосомы (рекомендуется) | Геномы человека, растений, грибов |

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta kmer=21
```

### `sln=` — Минимальная длина блока повтора

Задаёт минимальную длину (bp) области повтора для включения в результаты. Меньшие значения захватывают небольшие элементы (например, Alu ~300 bp, тРНК-SINE ~100 bp) ценой более фрагментированных результатов.

| Значение | Эффект |
|---|---|
| 20–59 | Захватывает очень короткие повторы (спейсеры CRISPR, миниатюрные транспозируемые элементы с инвертированными повторами (MITE)) |
| 60–80 | Хороший баланс для большинства анализов (по умолчанию) |
| 100+ | Отфильтровывает короткие элементы; фокус на более длинных повторах |

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta sln=100
```

### Многопоточная кластеризация

Кластеризация **многопоточна по умолчанию** — флаг не нужен. Попарное сравнение блоков, доминирующее на этапе кластеризации — косинус 4-меров для меры по умолчанию или вложенность k-меров при `-contain`, — и сопоставление семейств с библиотекой распределяются по доступным ядрам процессора, сокращая реальное время работы на геномах с множеством семейств повторов (измеренные времена: см. [Бенчмарк](#бенчмарк-чувствительность-и-скорость-на-смоделированных-геномах)). Это относится к обеим [мерам кластеризации](#меры-кластеризации). Сама детекция повторов — один потоковый проход по последовательности, и потоки ей не нужны.

Многопоточная кластеризация **детерминирована**: для заданных входных данных и набора параметров повторные запуски дают идентичные назначения кластеров и `ClusterID`, и результат не зависит от числа рабочих потоков. Детерминированность следует из конструкции — параллельный этап пишет только в приватные слоты каждого кандидата, а назначения применяются в порядке индексов — и была проверена сравнением результатов запусков с различным числом рабочих потоков. Число потоков влияет только на время работы.

```bash
# Многопоточность по умолчанию — флаг не нужен
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta
```

**`-normal` — однопоточная кластеризация.** Укажите `-normal`, чтобы выполнить кластеризацию в одном потоке вместо параллельной. На больших геномах это медленнее, но полезно для отладки или когда нужен именно однопоточный путь выполнения.

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta -normal
```

**Ограничение числа потоков без `-normal`.** Чтобы сохранить многопоточность, но ограничить число используемых рабочих потоков — например, на общем узле кластера или чтобы оставить ядра свободными для других заданий, — задайте стандартное свойство JVM *перед* `-jar`. Оно ограничивает общий пул Fork/Join Java, который использует параллельная кластеризация:

```bash
# Сохранить многопоточность, но ограничить её 8 рабочими потоками
java -Djava.util.concurrent.ForkJoinPool.common.parallelism=8 -Xms16g -Xmx32g -jar \
    TotalRepeats.jar genome.fasta
```

Значение `1` выполняет параллельный путь кода в одном потоке; `-normal` же выбирает отдельный однопоточный путь кода. Оба в итоге используют один поток, так что подойдёт любой вариант, когда нужно отключить параллелизм.

### Меры кластеризации

Группировать блоки повторов в семейства могут две разные меры, и они отвечают на разные вопросы. **Профиль состава 4-меров (`-vector`) используется по умолчанию**; `-contain` выбирает асимметричную вложенность k-меров. Обе работают без выравнивания, обе детерминированы, и обе учитывают случайность порогом, выведенным из данных, а не фиксированным порогом идентичности.

| Флаг | Мера | Группирует |
|---|---|---|
| *(нет)* или `-vector` | Состав 4-меров, сравниваемый по косинусу относительно порога случайного сходства, калибруемого для каждого запуска | **Дивергировавшие** копии, уже не разделяющие точных k-меров; блоки разной длины через окна согласованного масштаба, хотя вложенность при сильно различающихся размерах может быть упущена |
| `-contain` | Асимметричная вложенность по точным k-мерам | Блоки очень разной длины, включая короткий элемент внутри длинного |

#### `-vector` — профиль состава 4-меров (по умолчанию)

Каждый блок превращается в вектор сырых счётчиков по 238 каноническим 4-мерам, и два блока сравниваются по **косинусу** этих векторов в обеих ориентациях. Кандидат присоединяется к затравке, когда косинус превышает **порог случайного сходства, откалиброванный по данным самого запуска**, отдельно для каждого масштаба длин. Три элемента конструкции делают меру самокалибрующейся:

- **Порог случайного сходства для каждого масштаба длин.** Оценка, которую даёт одна лишь случайность, сильно зависит от длины блока и от генома: два *неродственных* окна длиной 250 bp в `MF782455` достигают косинуса, который единый плоский порог не отличит от настоящей гомологии, тогда как на 2 kb случайность никогда и близко не подходит. Это и не константа алгоритма — при 600 bp уровень случайности намного выше на композиционно однородном репликоне *E. coli*, чем на `MF782455`. Поэтому порог **измеряется для каждого запуска** по окнам входной последовательности, проверенным на отсутствие гомологии, а не зашит в код.
- **Окна согласованного масштаба.** Когда затравка намного длиннее кандидата, кандидат сравнивается с лучшим **окном** затравки своего масштаба, а не со всем составом затравки. Именно это позволяет увидеть короткий элемент, являющийся копией лишь *части* более длинного блока: реальная гомология повторов обычно частична, и усреднение по всему блоку размыло бы её.
- **Косинус по сырым счётчикам.** Сравнение полных векторов счётчиков сохраняет информацию о том, какие 4-меры **отсутствуют** — главный сигнал для короткого блока, — и даёт каждому блоку, каким бы коротким он ни был, что сравнивать.

Мера не требует поблочного индекса k-меров, поэтому её потребление памяти мало и почти постоянно, и это единственная мера, разрешающая гомологию, слишком дивергировавшую, чтобы разделять точные k-меры. Каждое сравнение — один проход слияния по двум разреженным векторам; калибровка для запуска стоит нескольких сотен построений оконных векторов, а оценка кандидата относительно плотных векторов окон затравки прямой индексацией делает сканирование окон дешёвым, так что `-vector` — более быстрая из двух мер на больших наборах блоков (см. [Бенчмарк](#бенчмарк-чувствительность-и-скорость-на-смоделированных-геномах)).

**Проверка выравниванием.** Большее число сгруппированных блоков само по себе не мера качества — слабый порог раздувает его шумом, — поэтому семейства проверялись по свидетельствам, не зависящим ни от одной из мер: разделяет ли член семейства точные 25-меры с затравкой своего семейства (вероятность совпадения заданного 25-мера в заданной позиции при равномерной модели оснований равна 4⁻²⁵), с решающей проверкой локальным выравниванием Смита–Ватермана (совпадение +2, несовпадение −3, открытие/продление гэпа −5/−2, обе ориентации) относительно нулевой модели, построенной перемешиванием затравки; пара признаётся гомологичной, когда её оценка не менее чем вдвое превышает её собственную перемешанную нулевую модель. На `MF782455` (вирусный геном 1.4 Mb; 765 блоков, не являющихся SSR, медианная длина блока 190 bp; параметры по умолчанию `kmer=19`, `sln=80`):

| Мера | блоков кластеризовано | членов с подтверждением 25-мерами | пар, подтверждённых Смитом–Ватерманом (случайная выборка из 50) |
|---|---|---|---|
| `-vector`, версия с фиксированным порогом из выпуска 3 | 205 | 67 | 52 % (26/50) |
| *(по умолчанию)* `-vector`, самокалибрующаяся | 436 | **354** | **98 %** (49/50) |
| `-contain` | 465 | 365 | 100 % (50/50) |

Средний столбец считает членов, разделяющих точные 25-меры с затравкой; правый столбец — вердикт Смита–Ватермана по случайной выборке пар «затравка–член». По сравнению с прежней версией с фиксированным порогом самокалибрующаяся мера находит примерно впятеро больше подтверждённых гомологичных членов при точности, близкой к `-contain`. Выигрыш зависит от генома: на `NC_014649` она группирует 75 блоков против 48 у `-contain`, и все 40 пар «член–затравка», случайно выбранных из этих 75, подтверждены выравниванием как гомологичные (40/40), хотя лишь около половины из 75 разделяют 25-мер со своей затравкой — состав распознаёт копии, дивергировавшие настолько, что не разделяют ни одного точного k-мера. На хромосоме *Pyricularia oryzae* длиной 7.5 Mb (`ch3_MG8`) она группирует 600 блоков с 88 % подтверждённых против 384 с 50 % у версии с фиксированным порогом.

#### `-contain` — асимметричная вложенность k-меров

Блок поглощается (более длинной) затравкой, когда большая доля его k-меров *встречается внутри* этой затравки; измерение ведётся по **каноническим** k-мерам, так что копия, вставленная в обратно-комплементарной ориентации, всё равно находится и помечается на минус-цепи:

```
C(A, B) = |kmers(A) ∩ kmers(B)| / |kmers(A)|   — how much of A occurs in B
```

Перенесена из [GeneDistance](https://github.com/rkalendar/GeneDistance). Поскольку она спрашивает «какая часть короткого блока содержится в длинном?», а не «насколько похожи их составы в целом?», она относит короткий элемент к более длинному повтору, который его содержит.

- Длина k-мера выбирается автоматически по медианной длине блока (нечётное значение в диапазоне 11–23), независимо от `kmer=`, используемого для *детекции* повторов.
- Коэффициент вложенности должен превышать собственный уровень случайности на пять стандартных отклонений, что удерживает ожидаемое число ложноположительных результатов ниже единицы на 10⁵–10⁶ проверок кандидатов большого запуска.
- Стоит примерно 8 байт на каждый уникальный k-мер каждого блока, поэтому для больших объединённых запусков выделите JVM достаточно кучи (`-Xmx`).

#### Сравнение двух мер

Две меры группируют действительно разные блоки. `-vector` (по умолчанию) быстра и почти не требует памяти; `-contain` стоит ~8 байт на уникальный k-мер каждого блока, но улавливает вложенность при сильно различающихся размерах (короткий элемент внутри длинного), которую состав может упустить.

```bash
# Кластеризация по умолчанию (профиль состава 4-меров) по пангеному
java -Xms16g -Xmx32g -jar TotalRepeats.jar /path/to/genomes/ -joint

# Вместо этого группировать гомологичные повторы разной длины по вложенности k-меров
java -Xms16g -Xmx32g -jar TotalRepeats.jar /path/to/genomes/ -joint -contain
```

Измерено с параметрами по умолчанию (`kmer=19`, `sln=80`) на `MF782455` и на 16 пластидных геномах, обработанных с `-collate`:

| Режим | MF782455 | 16 пластидных геномов, `-collate` |
|---|---|---|
| *(по умолчанию)* `-vector` | 436 блоков / 74 кластера | 176 / 41 |
| `-contain` | 465 / 92 | 179 / 31 |

#### Бенчмарк: чувствительность и скорость на смоделированных геномах

Приведённые выше цифры получены на реальных геномах, где истинное содержание повторов точно не известно. Чтобы измерить чувствительность напрямую, обе меры были также запущены на смоделированных геномах с заложенной эталонной разметкой: 20–30 семейств элементов длиной 500–2000 bp (см. таблицы ниже), каждый из которых вставлен 50–60 раз с фиксированной частотой замен на основание и разделён уникальными случайными спейсерами длиной 300–400 bp, сгенерированными с равными частотами оснований (≈50% GC). Размеры собранных геномов составили 1.2–2.4 Mb. Для каждого условия использовалось фиксированное начальное значение генератора случайных чисел, так что каждый запуск воспроизводим.

Два свойства делают сравнение мер контролируемым. Во-первых, **детекция повторов идентична** для обеих мер — различается только этап кластеризации, — поэтому обе оцениваются на в точности одном и том же наборе блоков. Во-вторых, гомология оценивается **по позиции внутри элемента** с поправкой на цепь: маскирование дробит элемент на куски, и два неперекрывающихся куска одного элемента — это разные последовательности, которые не должны группироваться. Оценка только по принадлежности к семейству штрафовала бы обе меры за решение, которое на самом деле верно.

Оценки попарные: *полнота* (recall) — доля действительно гомологичных пар блоков, помещённых в один кластер, а *точность* (precision) — доля пар, помещённых в один кластер, которые действительно гомологичны.

**Время работы** (секунды, реальное время, один запуск на условие — значения не усреднены; 4 ядра процессора, JDK 25, параметры по умолчанию. `-maskonly` изолирует общий этап детекции, поэтому столбцы кластеризации вычислены как общее − `-maskonly` и являются оценками):

|---|---|---|---|---|---|---|
| 2% дивергенции, 800 bp | 1556 | 1.0 | 2.3 | 1.8 | 1.3 | **0.9** |
| 8% дивергенции, 500 bp | 3762 | 1.3 | 4.9 | 7.5 | **3.6** | 6.2 |
| 10% дивергенции, 2000 bp | 7680 | 1.7 | 7.8 | 22.3 | **6.2** | 20.7 |
| 10% дивергенции, 50% обратно-комплементарных | 3126 | 1.0 | 3.6 | 6.8 | **2.6** | 5.8 |
| 15% дивергенции, 800 bp | 1379 | 1.0 | 3.1 | 2.4 | 2.1 | **1.4** |

**Чувствительность** (попарные оценки с учётом позиции на том же наборе блоков; «кластеров» — число выделенных кластеров в сопоставлении с числом заложенных семейств):

#### Выводы

1. **При низкой дивергенции `-contain` в этих симуляциях была более точной мерой.** При 2% замен она достигла попарной полноты 0.99 против 0.95 у `-vector` и выделила 20 кластеров для 20 заложенных семейств, тогда как `-vector` разбила их на 33. Она же была быстрее из двух на малых наборах блоков. `-contain` также группирует больше блоков на `MF782455` (465 против 436); как отмечено выше, число блоков само по себе не доказывает точности, но смоделированная эталонная разметка согласуется с реальным различием при низкой дивергенции.

2. **`-contain` резко деградирует с ростом дивергенции.** При 15% замен она кластеризует 6.0% блоков (полнота 0.007) против 44.9% у `-vector` (полнота 0.072) — разница в 7.5 раза по числу кластеризованных блоков и на порядок по полноте. Механизм — тот самый, на котором построены две меры: вложенность требует *точных* общих k-меров, которые замены разрушают, тогда как косинус состава по-прежнему различает сходство.

3. **`-vector` существенно чувствительнее на обратно-комплементарных копиях.** Когда половина вставок обратно-комплементарна, `-vector` кластеризовала 76.7% блоков против 34.6% у `-contain` и достигла примерно вдесятеро большей попарной полноты (0.249 против 0.023). Канонические k-меры дают `-contain` формальную независимость от цепи, но в сочетании с требованием точного совпадения она не переживает 10% дивергенции.

4. **`-contain` — более консервативная мера.** Там, где она вообще группирует, она редко ошибается (точность 0.71–1.00 по этим условиям), но группирует мало блоков; `-vector` охватывает более широкий диапазон (0.64–0.95), обменивая точность на многократный выигрыш в полноте. Обе оценки точности — нижние границы (см. «Ограничения»).

5. **Обе излишне дробят семейства, как только блоки фрагментированы**, выделяя намного больше кластеров, чем 20–30 заложенных семейств, и достигая попарной полноты лишь 0.007–0.25 в условиях с фрагментацией. Это выглядит общим потолком жадной схемы «затравка и поглощение», а не свойством какой-либо из мер, и является самой очевидной целью дальнейшей работы.

6. **Выше примерно 25% дивергенции выбор меры не имеет значения**, поскольку первой отказывает детекция: маскирование k-мерами при `kmer=19` нашло 18 блоков из 1000 заложенных вставок. Ограничивающий фактор тогда находится выше по конвейеру, в детекции, и средство — меньший `kmer=`, а не другая мера кластеризации.

7. **`-vector` лучше масштабируется с числом блоков.** Между запусками с 3762 и 7680 блоками время кластеризации выросло в 3.3 раза для `-contain` против 1.7 раза для `-vector`. На малых наборах блоков (~1500) `-contain` быстрее, поскольку `-vector` несёт фиксированные затраты на калибровку порога случайного сходства — 0.5–0.8 с по пяти условиям таблицы времени работы, — которые окупаются только на более крупных запусках.

#### Выбор меры

| Ситуация | Рекомендуется |
|---|---|
| Близкородственные копии (низкая дивергенция), малые наборы блоков | `-contain` — выше полнота при равной точности, и быстрее |
| Дивергировавшие копии (≳8% замен), обратно-комплементарные копии | `-vector` — полнота выше в несколько раз |
| Крупные запуски с множеством блоков повторов | `-vector` — заметно лучшее масштабирование |
| Дивергенция ≳25% | Ни одна; уменьшите `kmer=`, чтобы детекция сначала нашла копии |

Мера по умолчанию (`-vector`) подходит для типичных запусков геномного масштаба, сочетающих множество блоков, смешанную дивергенцию и обратно-комплементарные копии.

**Ограничения.** Это смоделированные последовательности с равномерными заменами и случайными спейсерами; реальные повторы несут также инсерции и делеции, вложенность одних элементов в другие и переменную длину копий, ничего из чего здесь не моделируется. Каждое условие запускалось один раз, на одной 4-ядерной машине, и времена включают запуск JVM; поскольку каждое условие запускалось однократно, приведённые времена не содержат оценки разброса между запусками. Оценка точности консервативна, так как блоки, покрывающие слегка смещённые области одного и того же элемента, оцениваются как негомологичные, поэтому приведённые значения — нижние границы. Абсолютная полнота зависит от того, насколько сильно маскирование дробит элемент, и потому является свойством этапа детекции в той же мере, что и меры кластеризации.

#### Замечания к обеим мерам

- Обе детерминированы и воспроизводимы и не зависят от числа рабочих потоков.
- `-homology` не выполняет кластеризации, поэтому ни один из этих флагов в том режиме не действует.
- Форма выходных данных одинакова для обеих мер — те же `ClusterID`, цепи, цвета, пофайловые и объединённые отчёты и пангеномная классификация, — так что выбор меры не влияет на последующие отчёты.
- Каждая опция сопоставляется как целый токен. `-vector` (по умолчанию) и `-contain` образуют пару включения/выключения; если указаны обе, побеждает `-contain`.

| Источник | URL | Примечания |
|---|---|---|
| **Dfam / FamDB** | <https://www.dfam.org/releases/current/families/FamDB> | Открытый доступ; экспортируйте консенсусные последовательности в FASTA для использования с `-lib=` |
| **Repbase** | <https://www.girinst.org/> | Требуется регистрация; курируемые консенсусные последовательности |
| **Собственная** | — | Соберите собственную FASTA-библиотеку для интересующего вида |

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta -lib=/path/to/library.ref
```

Семейство, совпавшее с записью библиотеки, помечается как `<n>:<name>` в столбце `Repeat` таблицы аннотации и в легенде рисунка, где *n* — позиция записи в библиотеке (отсчёт с 1), а *name* — её идентификатор FASTA. Семейства без совпадения сохраняют метку `CRP`.

### Сравнение сравнительных режимов

Все три сравнительных режима кластеризуют повторы *совместно* по всем входным файлам, и все три создают пофайловые отчёты, объединённый отчёт и пангеномный отчёт. Все три — как и `-homology` — требуют, чтобы входной путь был **папкой**; при передаче одиночного файла они игнорируются без предупреждения. Различаются они главным образом тем, как обнаруживаются повторы и какие пофайловые файлы записываются:

| Режим | Детекция повторов | Объединённое изображение | Пофайловые результаты | Пангеном | Типичное применение |
|---|---|---|---|---|---|
| `-collate` | маскирование k-мерами **для каждого файла отдельно**, затем совместная кластеризация | SVG | Таблица аннотации · PNG · SVG · маскированный FASTA | ✅ | Сравнение гомологичных хромосом / сборок |
| `-joint` | **одна общая таблица k-меров** по всем файлам — повтор, копии которого лежат в разных файлах, обнаруживается, — затем совместная кластеризация | SVG | Таблица аннотации · PNG · SVG · маскированный FASTA | ✅ | Рассматривать набор последовательностей как единое пространство поиска |
| `-combinemask` | повторы читаются из существующих мягко маскированных файлов (`.msk`), затем совместная кластеризация | SVG | Таблица аннотации · PNG · SVG | ✅ | Сравнение режимов маскирования / пангеномные исследования |

> Все три обрабатывают входной *пангеном* размером более ~2.1 GB — см. [Историю версий](#история-версий). Объединённое (межфайловое) изображение во всех режимах — SVG; пофайловые изображения — PNG **и** SVG.

### `-collate` — Сравнительный анализ

Выполняет синхронизированную кластеризацию повторов по нескольким последовательностям. Все файлы входной папки обрабатываются вместе, что позволяет напрямую сравнивать семейства повторов между геномами.

**Идеально подходит для:**
- Сравнения гомологичных хромосом разных видов или штаммов
- Выявления полиморфизмов повторов без полногеномного выравнивания
- Анализа сборок по длинным прочтениям (например, ONT, PacBio HiFi)

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar /path/to/sequences/ -collate
```

**Файлы, создаваемые запуском `-collate`:**

| Файл | Описание |
|---|---|
| `<file>.gff`, `<file>.png`, `<file>.svg` | Пофайловая аннотация и изображения для каждой входной последовательности |
| `<file>.msk` | Пофайловый мягко маскированный FASTA |
| `<report>.gff`, `<report>.svg` | Объединённая аннотация и изображение (SVG) по всем последовательностям |
| `<report>_pangenome.txt` | Сводка по пангеному (см. [Пангеномный отчёт](#пангеномный-отчёт)) |
| `<report>_pangenome.tsv` | Матрица числа копий семейств повторов (семейства × геномы) с категорией, уровнем, паттерном присутствия и статистикой числа копий |
| `<report>_pangenome_bp.tsv` | Та же матрица в покрытых bp |
| `<report>_pangenome_distance.tsv` | Квадратная матрица расстояний Жаккара между геномами |
| `<report>_pangenome.nwk` | Дерево UPGMA геномов (Newick, с длинами ветвей) |
| `<report>_pangenome.svg` | Четырёхпанельный пангеномный рисунок |

### Пангеномный отчёт

Каждый многогеномный сравнительный запуск (`-collate`, `-joint`, `-combinemask`) завершается пангеномным анализом совместно кластеризованных семейств повторов. **Геном** по умолчанию — один входной файл: все записи FASTA-файла с несколькими записями — хромосомы, контиги, плазмиды — считаются вместе, так что папка сборок сравнивает сборки, а не хромосомы. Укажите `-pangroup=record`, чтобы вместо этого считать геномом каждую запись FASTA (папка с единственным файлом из нескольких записей переходит к этому автоматически, поскольку один файл — не пангеном). Каждое семейство (кластер `CRP` с его `ClusterID`, как в `.gff`) сопоставляется с геномами, в которых оно встречается, что даёт профиль числа копий по геномам; содержание `UCRP` и `STR` сообщается по каждому геному в виде агрегатов. Из профилей отчёт выводит:

- **Классификация.** Каждое семейство является **коровым** (core; присутствует во *всех* геномах), **вспомогательным** (accessory; в некоторых) или **уникальным** (unique; ровно в одном). Поскольку эти три класса становятся слишком грубыми с ростом числа геномов, каждое семейство несёт также четырёхуровневую метку, используемую инструментами для бактериальных пангеномов: **core** ≥ 99 % геномов, **soft-core** 95–99 %, **shell** 15–95 %, **cloud** < 15 %.
- **Спектр частот семейств** — число (и bp) семейств, присутствующих ровно в *k* геномах: классическая U-образная пангеномная кривая.
- **Разрежение (rarefaction) и открытость.** Ожидаемый размер пангенома и размер кора при выборке *n* геномов для *n* = 1 … *N*. Они вычисляются **точно** из спектра частот — как среднее по всем *N*! упорядочениям геномов, — а не случайными перестановками, поэтому кривые воспроизводимы до последней цифры. Число новых семейств, вносимых *n*-м геномом, аппроксимируется законом Хипса (Tettelin *et al.* 2008), *n*(*N*) = κ·*N*^−α: **α ≤ 1 означает открытый пангеном** (новые семейства продолжают появляться), **α > 1 — закрытый**. Для аппроксимации нужно не менее трёх геномов, а при менее чем пяти она сообщается как оценка.
- **Расстояния между геномами и дерево.** Для каждой пары геномов: число общих семейств и семейств в объединении, сходство **Жаккара** по всем семействам и только по вспомогательным (коровые семейства общие по определению и лишь сжимают различия), а также несходство **Брея–Кёртиса** по числам копий, чувствительное к экспансиям семейств, которых присутствие/отсутствие не видит. Дерево **UPGMA**, построенное по расстоянию Жаккара, записывается в формате Newick для любой программы просмотра деревьев, а квадратная матрица расстояний — в TSV.
- **Паттерны присутствия.** Семейства группируются по точному набору геномов, в которых они встречаются (например, `1101` для четырёх геномов), с числом семейств и bp на каждый паттерн — это входные данные для UpSet-графика и быстрейший способ увидеть, какие подмножества геномов разделяют повторы, специфичные для отдельных линий.
- **Вариация числа копий.** Коровые семейства, число копий которых сильнее всего варьирует между геномами (коэффициент вариации, min/max, кратность диапазона), и **экспансии** по каждому геному: семейства, число копий которых не менее чем вдвое превышает среднее по остальным геномам и которые имеют не менее трёх дополнительных копий.
- **Сводка по каждому геному** — длина генома, присутствующие семейства по классам, bp корового / вспомогательного / уникального содержимого, а также число и bp `UCRP` / `STR` с процентом генома, который они покрывают.

`<report>_pangenome.txt` — удобочитаемая сводка всего перечисленного. `<report>_pangenome.tsv` — машиночитаемая матрица с одной строкой на семейство (плюс агрегатные строки `STR` и `UCRP`) и одним столбцом на геном, содержащим число копий; она сохраняет компоновку столбцов прежних выпусков и добавляет `Tier`, `Pattern`, `MinCopies`, `MaxCopies`, `MeanCopies` и `CV`. `<report>_pangenome_bp.tsv` содержит ту же матрицу в покрытых bp. Рисунок `<report>_pangenome.svg` показывает кривые разрежения с показателем Хипса, спектр частот, состав каждого генома и карту присутствия/отсутствия семейства × геномы под деревом UPGMA (когда семейств больше, чем можно нарисовать строк, последовательные семейства объединяются в бины, а непрозрачность ячейки показывает долю присутствующих). Все числа используют `.` в качестве десятичного разделителя независимо от системной локали.

> **Что считается семейством.** Повтор обнаруживается только там, где у него есть не менее двух копий в пространстве поиска — в пределах записи для `-collate` и `-combinemask`, по всему набору для `-joint`. Поэтому однокопийная последовательность, которую два генома просто разделяют, не образует семейства и не входит в этот пангеном; чтобы маскировать общую последовательность напрямую, используйте `-homology`.

### `-combinemask` — Сравнительный анализ на основе масок

Выполняет сравнительный анализ пангеномного масштаба, начиная с существующих мягко маскированных файлов. Обеспечивает синхронизированную кластеризацию и аннотацию по сборкам и позволяет сравнивать разные стратегии или параметры маскирования — включая маски, созданные другими инструментами.

Как и `-collate`, записывает **отдельную таблицу аннотации + PNG + SVG для каждого входного файла**, **объединённую таблицу + SVG** и полный **пангеномный отчёт** (см. [Пангеномный отчёт](#пангеномный-отчёт)). Пофайловый маскированный FASTA не записывается. См. [Сравнение сравнительных режимов](#сравнение-сравнительных-режимов).

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar /path/to/sequences/ -combinemask
```

### `-homology` — Маскирование гомологии

Маскирует все гомологичные области (как внутри входных последовательностей, так и между ними), чтобы выявить **уникальную, не общую последовательность**. Это обращает обычный вопрос поиска повторов: вместо «что повторяется?» он отвечает «что уникально?»

**Сценарии использования:**
- Выявление специфичной для линии последовательности между близкородственными геномами
- Сравнение хромосом X и Y человека
- Обнаружение штамм-специфичных инсерций или делеций

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar /path/to/sequences/ -homology
```

Результат — один мягко маскированный FASTA на входной файл; немаскированные (в верхнем регистре) участки — это уникальная последовательность, а `-extunique` записывает их в виде записей FASTA.

### `imgx=` — Масштабирование ширины изображения

Управляет горизонтальным разрешением выходных изображений (PNG и SVG). Большие значения дают более широкие и детальные изображения, удобные для приближения отдельных областей.

| Значение | Эффект |
|---|---|
| `1` | Максимальное сжатие — обзор всего генома |
| `10` | По умолчанию — подходит для большинства представлений на уровне хромосомы |
| `20–30` | Растянутое — детальный просмотр отдельных областей |

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta imgx=20
```

### `-readmask` — Импорт существующих масок

Импортирует заранее вычисленные файлы масок (например, из RepeatMasker или предыдущего запуска TotalRepeats) для кластеризации, аннотации и визуализации без повторного выполнения этапа маскирования. Строчные буквы читаются как повтор; файл с несколькими записями обрабатывается запись за записью.

```bash
java -Xms16g -Xmx32g -jar TotalRepeats.jar masked_genome.fasta -readmask
```

### `-readgff` — Импорт таблицы аннотации для визуализации

Импортирует таблицу аннотации, записанную TotalRepeats, и заново создаёт рисунки напрямую, минуя детекцию повторов (полезно после изменения `image=` или `imgx=`).

```bash
java -jar TotalRepeats.jar annotation.gff -readgff imgx=20
```

### `-extract` — Разбиение мульти-FASTA

Разбивает FASTA-файл с несколькими записями на отдельные файлы (по одному на запись последовательности). Полезно для подготовки входных данных, когда нужна обработка по хромосомам.

```bash
java -jar TotalRepeats.jar multi_entry.fasta -extract
```

Каждая запись записывается в `<id>.fasta`, где `<id>` — первое слово её заголовка. Символы, недопустимые в именах файлов (например, `|` в идентификаторах NCBI), заменяются на `_`, а повторяющийся идентификатор — или такой, который совпал бы с именем самого входного файла, — получает `_2`, `_3`, …, так что ни одна запись не перезаписывает другую; консоль перечисляет каждую запись, имя файла которой отличается от её идентификатора. `report.txt` даёт длину каждой записи и долю мягко маскированной последовательности; запуск на папке записывает один отчёт для всех её файлов.

### `-extunique` — Извлечение уникальных областей из маски

Обращение маски: берёт мягко маскированный FASTA (файл `.msk` из предыдущего запуска или любую последовательность, где повторы записаны строчными буквами) и записывает участки в **ВЕРХНЕМ РЕГИСТРЕ** — уникальную, неповторяющуюся последовательность.

Соседние участки в верхнем регистре, разделённые не более чем `gap=` основаниями, объединяются, и сохраняются только участки длиннее `sln=`, так что результат контролируют оба параметра:

```bash
java -jar TotalRepeats.jar genome.fasta.msk -extunique sln=100 gap=40
```

Результат — FASTA-подобный файл с именем `<input>.report` (`<input>_N.report` для каждой записи при входе из нескольких записей). Каждая извлечённая область несёт свои координаты в заголовке, с отсчётом от 1 и включительно:

```
>12345-67890
ATCGATCGATCG...
```

В отличие от `-homology`, который вычисляет маскирование сам, `-extunique` лишь читает существующую маску.

### `-maskscomp` — Сравнение инструментов маскирования

Сравнивает маскированные результаты разных программ (например, TotalRepeats и RepeatMasker). Требует управляющий файл **с разделителями-табуляциями**, перечисляющий пары последовательность/маска:

```bash
java -jar TotalRepeats.jar runfiles.txt -maskscomp
```

**Пример `runfiles.txt`:**

```
NC_017844.1.fasta	NC_017844.1.fasta.msk
NC_017849.1.fasta	NC_017849.1.fasta.msk
NC_017850.1.fasta	NC_017850.1.fasta.msk
```

## Форматы входных и выходных данных

### Вход: FASTA

TotalRepeats принимает стандартный формат FASTA или нуклеотидные последовательности в виде простого текста. Файл без строки заголовка читается как одна последовательность, названная по имени файла, при условии, что не менее 90% его букв — нуклеотидные коды (так что случайный текстовый файл во входной папке не анализируется как ДНК); текст перед первым заголовком FASTA-файла игнорируется. Коды неоднозначности IUPAC принимаются, `U` читается как `T`, а `I` — как `C`. Поддерживаются FASTA-файлы с несколькими записями: каждая запись анализируется отдельно и получает собственные выходные файлы, нумерованные по её позиции в файле — `<input>_N.gff`, `<input>_N.msk`, `<input>_N.png`, `<input>_N.svg` для записи *N* (в сравнительных режимах — `<file>_N_.gff` и т. д.). Запись не длиннее `-sln` пропускается с сообщением на консоли, так что её номер отсутствует в выходных файлах. Каждая отдельная последовательность (хромосома / запись) может быть размером до 2 GB; в сравнительных режимах (`-collate`, `-joint`, `-combinemask`) размер *пангенома* по всем файлам этим пределом не ограничен.

```
>sequence_id Optional description
ATCGATCGATCGATCGATCGATCG...
```

### Обзор выходных файлов

| Выходной файл | Формат | Описание |
|---|---|---|
| **Аннотации повторов** | Таблица с разделителями-табуляциями (`.gff`) | Координаты, классификация, цепь и принадлежность к семейству для каждого блока повтора |
| **Маскированный геном** | FASTA (`.msk`) | Мягко маскированная последовательность (повторы строчными буквами), 70 символов в строке; заголовок фиксирует % покрытия повторами |
| **Ландшафт повторов** | PNG / SVG | Векторная и растровая визуализация распределения повторов: дорожка всех повторов, дорожки STR и UCRP и по одной строке на семейство, где прямые копии показаны синим, а обратно-комплементарные — красным |
| **Сводная статистика** | Консоль и заголовки таблиц | Содержание повторов в геноме, содержание STR, содержание пробелов (N), время маскирования и общее время работы, идентификатор выпуска |
| **Пофайловые отчёты** *(сравнительные режимы)* | Таблица аннотации / PNG / SVG | Отдельная аннотация и изображения для каждого входного файла наряду с объединённым результатом |
| **Пангеномный отчёт** *(сравнительные режимы)* | Текст + TSV + Newick + SVG | Классификация core / soft-core / shell / cloud, разрежение и открытость по закону Хипса, расстояния между геномами с деревом UPGMA, паттерны присутствия, вариация числа копий, матрицы числа копий и bp и четырёхпанельный рисунок (см. [Пангеномный отчёт](#пангеномный-отчёт)) |

### Таблица аннотации повторов

Аннотации повторов записываются в виде таблицы с разделителями-табуляциями и строкой заголовка. Компоновка *похожа* на GFF3, но **не** соответствует спецификации [GFF3](https://github.com/The-Sequence-Ontology/Specifications/blob/master/gff3.md): столбцы содержат специфичные для TotalRepeats поля вместо `source`, `type`, `score` и `attributes` формата GFF3, и прагма `##gff-version 3` не записывается. Перед использованием в программах, работающих с GFF3, выполните преобразование. Расширение файла остаётся `.gff` для совместимости с существующими рабочими процессами.

Строки комментариев (`#`) в начале фиксируют выпуск, `kmer`, минимальную длину блока, длину последовательности, проценты повторов / STR / пробелов и время работы, за ними следует строка заголовка столбцов.

| Столбец | Поле | Описание |
|---|---|---|
| 1 | **Seqid** | Идентификатор последовательности (первое слово заголовка FASTA) |
| 2 | **Repeat** | Класс повтора: `STR` (короткий тандемный / низкой сложности), `UCRP` (некластеризованный диспергированный повтор), `CRP` (член кластеризованного семейства) или `<n>:<name>` для семейства, сопоставленного с записью *n* библиотеки `-lib=` |
| 3 | **ClusterID** | Идентификатор семейства: `1` — строка STR, `2` — строка UCRP, `3` и выше — семейства |
| 4 | **Start** | Начальная позиция (отсчёт от 1) |
| 5 | **Stop** | Конечная позиция (отсчёт от 1, включительно) |
| 6 | **Length** | Длина блока повтора (bp) |
| 7 | **Strand** | `+` (прямая) или `-` (обратный комплемент затравки семейства); всегда `+` для STR и UCRP |
| 8 | **Phase** | Всегда пусто (сохранено ради GFF-подобной компоновки столбцов) |
| 9 | **Sequence** | Только с `-seqshow`: последовательность блока от Start до Stop, обратно-комплементарная для копий на цепи `-`, с `flanks=` основаниями фланкирующей последовательности в верхнем регистре с каждой стороны (фланги обрываются на границе записи) |

Строки содержат восемь полей, разделённых табуляциями, без `-seqshow` и девять с ним; последовательность, если присутствует, всегда является последним полем.

## Устранение неполадок

### Нет входного файла (вместо результатов печатается справка)

Если запустить TotalRepeats без аргументов, с явным флагом справки или с первым аргументом, который не является существующим файлом или папкой, программа печатает справку и завершается, ничего не анализируя:

```bash
# Явный запрос справки — печатает справку и выходит
java -jar TotalRepeats.jar --help

# Нет входных данных (только опции) — печатает справку
java -jar TotalRepeats.jar -kmer=18 -seqshow

# Неверный путь — печатает «input file or folder not found» + справку
java -jar TotalRepeats.jar /no/such/genome.fasta
```

Убедитесь, что **входной файл или папка — первый аргумент**, перед любыми опциями:

```bash
java -jar TotalRepeats.jar genome.fasta -kmer=18 -seqshow   # правильно
```

Распознаваемые флаги справки перечислены в разделе [Базовый синтаксис](#базовый-синтаксис).

### Ошибки версии Java

Убедитесь, что Java 25 или выше установлена и активна:

```bash
java -version
```

Если установлено несколько версий Java, задайте `JAVA_HOME` явно:

```bash
export JAVA_HOME=/path/to/jdk-25
export PATH="$JAVA_HOME/bin:$PATH"
```

### `OutOfMemoryError`

Увеличьте выделение кучи согласно таблице [Настройка памяти](#настройка-памяти):

```bash
java -Xms16g -Xmx64g -jar TotalRepeats.jar genome.fasta
```

> **Совет:** если на вашей машине мало ОЗУ, попробуйте `-maskonly`, чтобы пропустить кластеризацию, — этап маскирования использует значительно меньше памяти.

> **`Requested string length exceeds VM limit` в сравнительном запуске:** эта конкретная ошибка возникала в сравнительном коде выпусков до 4.0 (`-collate`/`-joint`/`-combinemask`), который строил одну строку из всей конкатенации, а Java ограничивает её ~2.1 GB. Она устранена — теперь эти режимы конкатенируют виртуально и используют 64-битные координаты. Если вы всё же сталкиваетесь с обычным `OutOfMemoryError` (куча), увеличьте `-Xmx` по таблице выше.

### Повторы не обнаружены

- **Проверьте размер k-мера:** для малых геномов или коротких повторов уменьшите `kmer` (например, `kmer=12`).
- **Снизьте минимальную длину:** уменьшите `sln` (например, `sln=30`), чтобы захватить более короткие элементы.
- **Проверьте входные данные:** убедитесь, что FASTA-файл содержит корректную нуклеотидную последовательность.

### Выходные изображения слишком малы или слишком сжаты

Увеличьте коэффициент масштабирования изображения:

```bash
java -jar TotalRepeats.jar genome.fasta imgx=30
```

Или задайте точные размеры:

```bash
java -jar TotalRepeats.jar genome.fasta image=4000x2000
```

### Медленная кластеризация на больших геномах

Кластеризация многопоточна по умолчанию и уже использует все доступные ядра процессора — прежде всего убедитесь, что вы **не** указали `-normal`, который принудительно включает более медленный однопоточный путь:

```bash
# Многопоточность по умолчанию — НЕ добавляйте -normal
java -Xms16g -Xmx32g -jar TotalRepeats.jar genome.fasta
```

Чтобы ограничить число рабочих потоков (например, на общем узле), сохранив многопоточность, добавьте `-Djava.util.concurrent.ForkJoinPool.common.parallelism=N` перед `-jar`. Многопоточная кластеризация детерминирована, поэтому число потоков меняет только время работы, но не результат.

## Часто задаваемые вопросы

**В: Нужна ли TotalRepeats готовая библиотека повторов?**
Нет. TotalRepeats выполняет детекцию *de novo* на основе анализа k-меров — внешняя библиотека не нужна. Однако при желании можно передать библиотеку (Repbase, Dfam или собственную) через `-lib=`, чтобы дать имена обнаруженным семействам повторов.

**В: Какие организмы поддерживает TotalRepeats?**
Любой организм, для которого есть последовательность ДНК. TotalRepeats работает только с нуклеотидной последовательностью и не делает таксон-специфичных допущений; он применялся к геномам вирусов, бактерий, грибов, растений и животных.

**В: Как TotalRepeats соотносится с RepeatMasker?**
RepeatMasker опирается на курируемую библиотеку (Repbase/Dfam) и выполняет детекцию по гомологии — он может найти только повторы, представленные в его базе данных. TotalRepeats обнаруживает повторы *de novo*, без предварительной аннотации, хотя чувствительность падает по мере дивергенции копий: в симуляции детекция при `kmer=19` находила мало копий за пределами ~25% замен (см. [Бенчмарк](#бенчмарк-чувствительность-и-скорость-на-смоделированных-геномах)). Подходы взаимодополняющи: детекция *de novo* — для открытия, поиск по библиотеке — для классификации. Опция `-maskscomp` позволяет напрямую сравнить их результаты, а `-readmask` позволяет TotalRepeats кластеризовать и отрисовать маску, созданную RepeatMasker.

**В: В чём разница между TotalRepeats и конвейером de novo вроде RepeatModeler?**
Конвейер *de novo* связывает в цепочку несколько программ (поиск на основе k-меров или выравнивания, построение консенсусов, классификация, маскирование), у каждой из которых своя установка и свои параметры. TotalRepeats выполняет поиск, детекцию STR, кластеризацию семейств, определение цепи, маскирование, необязательное именование, рисунки и пангеномное сравнение в одной программе без зависимостей, без какого-либо этапа выравнивания, а его порог кластеризации калибруется по данным, а не фиксирован.

**В: Можно ли обрабатывать несколько геномов сразу?**
Да. Укажите TotalRepeats папку с FASTA-файлами, и он обработает их все. Добавьте `-collate` (или `-joint` / `-combinemask`) для синхронизированной межгеномной кластеризации повторов — каждый из этих режимов создаёт пофайловый отчёт и изображение для каждого входного файла, объединённый отчёт и изображение, а также пангеномный отчёт (коровые / вспомогательные / уникальные и core / soft-core / shell / cloud семейства, кривые разрежения с законом Хипса, расстояния между геномами и дерево UPGMA, паттерны присутствия, вариация числа копий, матрицы и рисунок). Каждый входной файл считается одним геномом; `-pangroup=record` вместо этого сравнивает записи FASTA. См. [Сравнение сравнительных режимов](#сравнение-сравнительных-режимов) и [Пангеномный отчёт](#пангеномный-отчёт).

**В: Каков максимальный размер генома, с которым справляется TotalRepeats?**
TotalRepeats протестирован на геномах размером более 20 Gb (например, *Pleurodeles waltl*). Одна последовательность (одна запись FASTA) ограничена 2 GB из-за предела массивов/`String` в Java, но в сравнительных режимах *суммарный* размер по файлам не ограничен — эти режимы конкатенируют виртуально и используют 64-битные координаты. Практический ограничивающий фактор — доступная ОЗУ, поэтому выделите достаточно кучи через `-Xms` / `-Xmx`.

**В: Воспроизводимы ли результаты?**
Да. При тех же входных данных и параметрах каждый режим записывает побайтово идентичный результат при каждом запуске и при любом числе потоков: параллельная кластеризация детерминирована по построению, пангеномное разрежение вычисляется точно, а не случайными перестановками, и ни один этап не использует случайное начальное значение. Идентификатор выпуска записывается в каждую таблицу аннотации, так что версию, стоящую за любым результатом, можно восстановить из самого результата.

**В: Можно ли импортировать результаты других инструментов?**
Да. Используйте `-readmask` для импорта маскированных FASTA-файлов из RepeatMasker или других инструментов и `-readgff` для перерисовки рисунков по таблице аннотации, записанной TotalRepeats.

**В: Что именно делает флаг `-normal`?**
По умолчанию кластеризация многопоточна — этап попарного сравнения выполняется на всех ядрах процессора, сокращая реальное время кластеризации на геномах с множеством семейств повторов (измеренные времена: см. [Бенчмарк](#бенчмарк-чувствительность-и-скорость-на-смоделированных-геномах)). Указание `-normal` отключает это и выполняет кластеризацию в одном потоке: медленнее, но полезно для отладки или когда нужен однопоточный путь кода. Если вы хотите сохранить многопоточность, но лишь ограничить число рабочих потоков, вместо этого добавьте `-Djava.util.concurrent.ForkJoinPool.common.parallelism=N` перед `-jar` (см. [Многопоточная кластеризация](#многопоточная-кластеризация)). Многопоточный путь детерминирован: повторные запуски дают идентичные назначения кластеров и `ClusterID` независимо от числа потоков.

## История версий

**4.1.3** — Согласованная таблица аннотации и документация, пересмотренная для рецензирования. Таблица, записанная с `-seqshow`, теперь содержит последовательность в собственном девятом столбце, после (пустого) столбца `Phase`, так что строки данных соответствуют заголовку. Текст `--help` переписан: описаны все режимы и опции, добавлен `-version`, примеры соответствуют текущим режимам. Документация (README, обзор, схема рабочего процесса, текстовый readme, руководство Word) приведена в соответствие с кодом и дополнена измеренным временем работы; руководство Word теперь собирается из README скриптом `tools/md2docx.py`. Детекция повторов, маскирование, кластеризация и сравнительные режимы не изменились по сравнению с 4.1.0.

**4.1.2** — FASTA-файлы с несколькими записями, запись за записью. Записи короче k-мера, пустые записи и записи, состоящие целиком из пробелов, больше не приводят к сбою сравнительных режимов и не выдают `NaN`; текст перед первым заголовком игнорируется; нуклеотидная последовательность без заголовка читается как одна запись; `-extract` записывает корректные, различающиеся имена файлов и никогда не перезаписывает свой входной файл; `-joint` / `-homology` называют свои маски по записи, как это делает `-collate`. Детекция повторов, маскирование и кластеризация не изменились по сравнению с 4.1.0.

**4.1.1** — Каждая запись мульти-FASTA получает собственные выходные файлы — `<input>_N.gff`, `_N.msk`, `_N.png`, `_N.svg` — со своим именем, статистикой и последовательностями; последовательности `-seqshow` идут точно от Start до Stop с флангами, обрывающимися на границе записи.

**4.1.0** — Пангеномный анализ перестроен. Отчёт `-collate`, `-joint` и `-combinemask` рассматривает каждый входной файл как один геном (`-pangroup=record` возвращает один геном на запись) и добавляет четырёхуровневую классификацию core / soft-core / shell / cloud, точные кривые разрежения с аппроксимацией по закону Хипса, расстояния Жаккара и Брея–Кёртиса с деревом UPGMA в формате Newick, паттерны присутствия, вариацию числа копий и четырёхпанельный рисунок SVG. Новые файлы: `_pangenome_bp.tsv`, `_pangenome_distance.tsv`, `_pangenome.nwk`, `_pangenome.svg`. Числа записываются с десятичным разделителем `.` независимо от системной локали.

**4.0** —
- *Самокалибрующаяся кластеризация.* Мера состава 4-меров (`-vector`, теперь по умолчанию) сравнивает сырые счётчики 4-меров по косинусу относительно порога случайного сходства, откалиброванного для каждого масштаба длин по данным самого запуска, и сопоставляет длинные затравки окно за окном; на `MF782455` это подняло долю сгруппированных пар, подтверждённых Смитом–Ватерманом, с 52 % до 98 % при впятеро большем числе подтверждённых гомологичных членов (см. [Меры кластеризации](#меры-кластеризации)). `-contain` вместо этого выбирает вложенность по точным k-мерам.
- *Сравнительные запуски пангеномного масштаба.* `-collate`, `-joint` и `-combinemask` конкатенируют входные данные виртуально и адресуют их 64-битными координатами, так что суммарный объём входных данных больше не ограничен ~2.1 GB (`Requested string length exceeds VM limit`).
- *Пофайловые отчёты в каждом сравнительном режиме* как точные срезы совместной кластеризации, так что семейство сохраняет тот же `ClusterID`, цвет и метку в каждом представлении; объединённое изображение записывается в SVG.
- *Многопоточная кластеризация по умолчанию*, детерминированная и не зависящая от числа потоков; `-normal` выбирает однопоточный путь.
- *Токенный разбор командной строки*: опции сопоставляются как целые слова, без учёта регистра, с необязательным ведущим дефисом; путь, содержащий имя опции, больше не включает эту опцию, а нераспознанные опции сообщаются.
- *Производительность*: подсчёт k-меров переведён на множество с открытой адресацией без значений (`LongCountSet`), а внутренние циклы детектора STR и кластеризации оптимизированы.
